Logbook

Evidence from a self-hosted VLAN-segmented home lab running a production-grade honeypot, SIEM, and firewall stack, plus an isolated OSINT segment for threat intelligence work. Everything here comes from a live environment: real attackers hitting the honeypot, and real adversary infrastructure observed from the research VLAN.

01

Lab Infrastructure

The entire stack runs on a single physical host. Building it from scratch — rather than using a managed service — means owning every configuration decision, from hypervisor to VLAN tagging to firewall policy.

PROXMOX VE · VM INVENTORY

Virtual machines running concurrently on a single physical host: the OPNsense firewall, Wazuh SIEM manager, Cowrie honeypot, the Parrot OS OSINT workstation on its own isolated VLAN, and supporting services. Uptime across the board confirms persistent operation, not a one-time demo.

802.1Q VLAN CONFIG · MANAGED SWITCH

VLANs 10 (Trusted), 20 (Honeypot), 30 (Management), 40 (IoT), and 50 (OSINT) defined with explicit tagged/untagged port assignments. Port 1 carries the 802.1Q trunk to the router; each downstream port lands on exactly one VLAN. Management and OSINT exist only as tagged VLANs on the trunk, so they are reachable from VMs but have no physical port at all.

02

Network Security Architecture

Every rule in the firewall was written intentionally. Inbound SSH is redirected to the honeypot via NAT. The Trusted VLAN is explicitly blocked from reaching the Honeypot network. These aren't defaults — they're design decisions you can read directly from the ruleset.

OPNSENSE · FIREWALL RULES

The ruleset shows deliberate segmentation: inbound SSH from WAN is passed to the honeypot, Trusted network is explicitly blocked from reaching Honeypot network, and a separate rule gates admin access to the Cowrie VM on a non-standard port. Rule descriptions are written to be auditable.

OPNSENSE · LIVE FIREWALL LOG live traffic

Live log showing real external IPs matching Allow inbound SSH to honeypot and triggering the rdr redirect. Each inbound connection generates three log lines — WAN in, NAT redirect, and Honeypot out — confirming the full redirect chain is functioning. Destination IPs are redacted.

03

Threat Detection & SIEM

Wazuh aggregates logs from across the lab and correlates them against MITRE ATT&CK. The dashboards below were built to give a quick operational read on threat volume, attack technique distribution, and honeypot activity.

WAZUH · CUSTOM SOC DASHBOARD

43,104 total alerts in the last 24 hours; 42,184 (97.9%) from the honeypot. Top destination port is SSH at 100% — the entire exposed attack surface is deliberate and contained. The dashboard was built to give a one-glance read on honeypot activity versus everything else.

WAZUH · AGENT OVERVIEW · DOLOS

MITRE tactic distribution over 24 hours: Execution at 8,292 events, with Defense Evasion, Initial Access, Persistence, and Privilege Escalation each at 4,673 — a pattern consistent with credential stuffing followed by automated post-login enumeration.

WAZUH · MITRE ATT&CK DASHBOARD

Filtered to agent 004 (DolosHoney). The alert cadence chart shows repeated burst cycles; the bar chart breaks down attack volume by MITRE tactic. Seeing the pattern — not just individual alerts — is what distinguishes detection from monitoring.

05

OSINT & Threat Intelligence

When a local organization was hit by Interlock ransomware, I built a dedicated research segment to investigate it safely: VLAN 50 is firewalled off from every internal network, egresses only through a VPN, and runs a Parrot OS workstation with Tor Browser. From there I corroborated the ransom note's negotiation portal against ransomware.live's infrastructure data and monitored the group's leak site for a victim posting. The victim is deliberately not identified anywhere on this page.

PROXMOX · ATHENA · OSINT WORKSTATION VLAN 50

Parrot Security VM (Athena) with its NIC tagged tag=50 on vmbr0, so it lands on the OSINT VLAN with no path to Trusted, Management, or Honeypot. Nothing of value lives on it, so it can be rebuilt from the ISO at any time.

OPNSENSE · OSINT VLAN RULESET

Two rules, evaluated top down: a block from OSINT network to an RFC1918 alias covering 10/8, 172.16/12, and 192.168/16, then an allow to anywhere. A compromised research box can reach the internet and nothing inside the lab. Traffic then leaves through IPVanish before Tor, so neither the VPN nor the exit node sees both ends.

RANSOMWARE.LIVE · INFRASTRUCTURE CORROBORATION interlock

The ransom note pointed to a .onion negotiation portal at /chat.php. ransomware.live lists the same host as Interlock's known infrastructure, with the leak site at /leaks.php. Matching the note's address to independently tracked group infrastructure confirmed attribution without touching the victim's systems.

TOR · ADVERSARY LEAK SITE

The group's leak site, reached over Tor from the OSINT VLAN. Interlock frames itself as punishing negligence rather than extorting; the same templated language shows up in every ransom note. Monitoring here is how you learn whether negotiations failed, because victims appear on the leak page before any public notification.
